# VERIFY: sandbox checks for FairCancel

Run on 2026-11-12 against the sandbox; results are in the Result column. S7, S10 and V13 are still open. The Judge-mode screen walk on the sandbox (S11) passed. The app, the tests and the build never call PayPal or Anthropic; a person runs these after approving it, in this order, with sandbox credentials in `.env` (use a sandbox business account that no other project uses). The model checks (C1) were run through the local Claude Code account (`LLM_BACKEND=account`), never through an API key, so they do not verify the hosted API path.

Setup, once:

```bash
npm install
node scripts/seedLive.js plan          # product + $9/week plan through the Agent Toolkit
node scripts/seedLive.js create 3      # 3 subscriptions, approval links in data/seeds.pending.json (or: bash scripts/topUpSeeds.sh 60)
SANDBOX_BUYER_EMAIL=... SANDBOX_BUYER_PASSWORD=... python3 scripts/approveSeeds.py   # or open each link by hand
node scripts/seedLive.js collect       # re-run until the seeds show "ready"
```

## C1 results (account-mode Sonnet `claude-sonnet-5-5`, 2026-11-12, PayPal on the local stand-in)

Each case ran once, hero (b) four times. All answers came from the model (`agentKind` = `claude-account`).

| Case | Sentence | Tools in order | Rule card | Agent (model) | Time |
|---|---|---|---|---|---|
| hero (a) | Visiting family until mid-January, then I will be back | get_policy, get_subscription_state, propose_offer | pause 2 weeks | pause 8 weeks (you said mid-January) | 8.7 s |
| hero (b) | Back after the holidays, my kid is home | get_policy, get_subscription_state, propose_offer | pause 2 weeks | pause 8 weeks (you said "after the holidays") | 7.2 s |
| billing | I was charged yesterday but couldn't make any class this week | get_policy, list_recent_payments, get_usage_record, quote_refund, propose_offer | no offer | no offer | 7.0 s |
| too expensive | too expensive | get_policy, get_usage_record, quote_refund, propose_offer | no offer | no offer | 7.5 s |
| hero (b) runs 2 to 4 | same | same three tools | pause 2 weeks | pause 8 weeks every time | 8.0, 7.3, 5.7 s |

Findings: the model reads "after the holidays" (a sentence the keyword code cannot read) as about 7 weeks from Nov 12 and picks the 8 week menu value, which the server kept as is because no return time can be read by code. Tool order matched the stand-in. The model never called a tool that moves money (none exists). One run in four came in under 6 s, so the account path needs the longer timeout; the hosted API path was not measured.
